# Data Model: Book and Author

## Author

Represents a person credited with one or more books.

| Field | Type | Required | Rules |
|---|---|---:|---|
| `_id` | BSON ObjectId | Yes | Generated by MongoDB/application; stable persisted identity |
| `name` | string | Yes | Trimmed; 1–255 characters |
| `normalizedName` | string | Yes | Internal normalized value for duplicate detection and migration matching; unique index |
| `biography` | string | No | Optional profile text |
| `website` | string | No | Optional absolute HTTP/HTTPS URI |
| `birthDate` | date/time | No | Optional; valid calendar date |
| `nationality` | string | No | Optional country of origin |
| `email` | string | No | Optional valid email address |
| `active` | boolean | Yes | Defaults to `true`; soft deletion sets `false` |
| `createdAt` | UTC date/time | Yes | Set on creation; immutable |
| `updatedAt` | UTC date/time | Yes | Set on creation and each state change |

The API exposes `_id` as string `id`; it does not expose MongoDB-specific field names. Email is the contact field in v1; phone and postal-address fields are not specified.

## Book

Retains the existing catalog entity and fields:

| Field | Type | Required | Rules |
|---|---|---:|---|
| `_id` | BSON ObjectId | Yes | Existing stable identity |
| `title` | string | Existing behavior | Preserve current semantics |
| `authorId` | BSON ObjectId | No | New reference to one Author; validate active Author on new association |
| `author` | string | No | Legacy display/input field retained during transition |
| `categoryId` | integer | Existing behavior | Preserve current category mapping |
| `quantity` | integer | Existing behavior | Preserve current behavior |
| `description` | string | Existing behavior | Preserve current behavior |
| `language` | string | Existing behavior | Preserve current behavior |
| `active` | boolean | Existing behavior | Author deletion does not change this field |
| `inactiveDate` | date/time | Existing behavior | Preserve current behavior |
| `publisher` | string | Existing behavior | Preserve current behavior |
| `publisherDate` | date/time | Existing behavior | Preserve current behavior |

## Relationships and lifecycle

- One Author can be related to zero or many Books. Each Book has zero or one `authorId`.
- Deleting an Author is a soft-delete state transition: `active: true` → `false`; update `updatedAt`. It does not remove the Author or mutate Books.
- Active-only list/get is the default. `includeInactive=true` permits retrieval of inactive Authors.
- A Book filter by `authorId` uses the stable ObjectId reference and can return books whose Author is inactive; soft deletion does not hide historical catalog entries.
- Duplicate author detection uses trimmed, case-normalized names and a unique index. Name is not the reference key.

## Migration and validation

- Backfill each distinct normalized nonblank legacy Book `author` into one Author and set the Book's `authorId`.
- The backfill must be idempotent, preserve existing valid `authorId` values, and leave the legacy string untouched.
- Books with blank author values remain unlinked and are reported.
- Conflicting or ambiguous normalized names must be reported for review; do not silently merge or delete profiles.
- For new Book writes, an explicit `authorId` must parse and refer to an active Author. Legacy `author` input resolves an active Author by normalized name and creates a minimal Author if none exists.
- Author name is required and at most 255 characters. Website, when present, must be an absolute HTTP/HTTPS URI. Email, when present, must be valid.
